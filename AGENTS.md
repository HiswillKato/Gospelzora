# AGENTS.md

Gospelzora — a plain-PHP gospel music platform at `/var/www/zora`. No framework, no npm, no build step. Bootstrap 5 + Font Awesome 6 + jQuery are committed locally under `assets/` (strict CSP means nothing loads from a CDN). Composer is used for exactly one package (`phpmailer/phpmailer`, committed in `vendor/`, web-blocked by `vendor/.htaccess`). This folder is **not** a git repo — there is no `.git`, so nothing here has version history and every change is verified by hand.

## Stack & verification

- PHP 8.5 (uses `match`, `str_ends_with`, spread in `bind_param`). MariaDB 11.8 on localhost.
- **One config file: `app/config.php`** — working defaults, the live DB credentials, mail settings and `GOSPELZORA_HOSTS` all live there, and it is world-readable (`0755 root:root`), so treat its contents as public. `app/config.local.php` was removed; if it is ever dropped back in, `config.php` still honours it and it wins (it guards itself with the `CONFIG_ACTIVE` sentinel). `.gitignore` still ignores it.
- Mail: **Postfix** on loopback (`127.0.0.1:25`) + PHPMailer via the `Mail` class, sending as `mail@mail.local`. Outbound is local-only unless a relay is configured — mail to external domains usually fails, while local `*@mail.local` delivers to `/var/mail/<user>`. PHPMailer tries STARTTLS by default, so `Mail::transport()` sets `SMTPAutoTLS=false` and `SMTPSecure=''`. Dovecot (IMAP) serves real-Unix-user mailboxes on `mail.local` and needs `auth_allow_cleartext=yes` + `auth_username_format = %{user|username|lower}`; `MAIL_ADMIN` is `hiswill@mail.local`, and `info@`/`noreply@` are aliases to the `mail` account.
- DB: `mysql -u root -proot zora` (creds in `app/config.php`). `database.sql` is schema + the 19 bootstrap `pages` SEO rows (drop/recreate; idempotent) — no accounts, songs or categories. Accounts live in one `users` table with a `role` column (`user|artist|admin`); `songs.artist` points at `users.id`, `users.verified` gates public login, and the `tokens` table holds one-time hashed tokens for `email_verify`/`password_reset`. Live demo data exists only in the live DB. See *Database naming is ONE word* below.
- **No automated test suite and no CI** — the `tools/` harness and its `verify.sh` baselines were deleted. Nothing mechanically proves a change; verification is manual:
  - `php -l` on changed files: `find . -name '*.php' -not -path './vendor/*' -exec php -l {} \;`
  - `mysql` checks for anything touching data, and a `mysqldump` before any of it.
  - Walk changed routes by hand: `curl -s -o /dev/null -w '%{http_code} %{size_download}\n' -H 'Host: zora' https://127.0.0.1/<route>`. The site is served by the **`zora` vhost only** (`localhost` answers on a different docroot via `local.conf`), so the `Host:` header is mandatory; HTTP :80 redirects to HTTPS with a 301.
  - Read the **byte size**, not just the status code: a `__DIR__`-depth mistake or a collapsed `asset()` path still returns 200 with valid-looking markup (see the `asset()` gotcha).
- Filesystem is the router: `pages/*.php` public pages, `dashboard/*.php` member area, `dashboard/admin/*.php` admin panel, `api/*.php` AJAX endpoints, `installer.php` setup wizard. Pretty URLs come from the root `.htaccess` (`RewriteBase /`) mapping to `?slug=` params; numeric slugs fall back to id lookup for legacy links. Adding a public page means adding a `.htaccess` rule.

## Layout

```
app/          core, denied over HTTP
  config.php              constants + secure-session/header bootstrap + COUNTRY_LIST
  bootstrap.php           THE entry point (see below): config, functions, seven classes,
                          ONE shared instance of each, then the two request-wide gates
  functions.php           ALL 32 general helpers, one file, sectioned by concern
  db.class.php            the mysqli data layer (select/row/scalar/execute/insert)
  settings.class.php      key/value settings (the maintenance flag)
  user.class.php          accounts + the access-control guards
  music.class.php         songs, categories, favorites, song requests, playlists
  analytics.class.php     activity log, login records, visitors, downloads
  mail.class.php          the single outbound-email path
  pages.class.php         per-page SEO metadata
  includes/               the three shells (public/, admin/, member/) plus partials/
                          and the standalone db-error.php / maintenance.php cards
pages/        25 public pages (cannot be denied — see gotchas)
dashboard/    member pages + includes/, and admin/ + includes/
api/          AJAX endpoints (artists, favorite, icons, player, playlist, search)
assets/       css, js, webfonts, images, audio
installer.php the one-shot setup wizard, ONE self-contained file (reachable on purpose)
```

`app/` and `vendor/` are denied twice: by the `.htaccess` rules and by `<DirectoryMatch>` blocks in the `zora` vhost, so the block survives a removed `.htaccess` or a broken `AllowOverride`. `installer.php` is deliberately **not** denied by `.htaccess` — it is the wizard's entry point and refuses to run while `install.lock` exists (it does on this box); the vhost denies it via `<LocationMatch>`, commented out until after the first install. `index.html` is a leftover Serv00 hosting placeholder, harmless — the router answers `/`.

## Config & serving

- **The router pins the docroot.** `.htaccess` carries a literal `RewriteBase /`, so the project must be served from the document root; a subdirectory install needs `RewriteBase /<subdir>/` changed to match. The vhost must set `DocumentRoot` to this folder with `AllowOverride All` — with `None`, every pretty URL 404s while `/pages/*.php` still works, which reads as a rewrite bug rather than a config one.
- **`BASE_URL` must be pinned to the real live domain.** Otherwise it is derived from the `Host` header, subject to `GOSPELZORA_HOSTS` (`['zora', 'www.zora', 'localhost', '127.0.0.1']`); a host missing from that list falls back to `http://localhost/` and every asset/link points at the visitor's machine. The production self-check in `app/bootstrap.php` turns exactly that case into a styled 503 (`app/includes/config-error.php`) instead of a plausible-looking broken page.
- **Do not make the `admin/` 301 relative.** Apache resolves a relative `[R=301]` substitution against the filesystem and emits `https://host/var/www/zora/dashboard/admin/…`; it was tried and reverted.
- HSTS is deliberately **not** sent. It is browser-enforced for its `max-age`, so enabling it on a host with a broken certificate locks out every visitor who already has the header. The header stack that IS set lives in `config.php`: CSP (`default-src 'self'`, no `unsafe-eval`), `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, and `upgrade-insecure-requests` over HTTPS.

## `app/bootstrap.php` is the entry point

Every page, API endpoint and view partial starts with `require_once __DIR__ . '/<relative>/app/bootstrap.php';`. That include is what makes the framework live: load `config.php`, require `functions.php` then the seven class files, build the **one shared instance** of each in the dependency order `DB → Analytics → Mail → Settings → User → Music → Pages`, then run the two request-wide gates (maintenance, exception handler). It contains no domain logic. The load order matters because the maintenance card and the exception handler render full pages through the partials, which need `e()`, `icon()`, `asset()` — so `functions.php` must load before the gates run.

## Naming is the contract (hard rules)

- **Every function and method name is ONE word** — no `snake_case` pairs, no camelCase. Where a rename would collide, **invent a distinct single word** (`store()` for the write, `state()` for the read, `burn()` for token invalidation, `hit()` for a cooldown increment). Where two helpers differed only by an argument, merge into one function with a mode argument (see Architecture). `AGENTS.md`, `database.sql` comments and every caller are updated in the same change — a rename that leaves a stale reference is unfinished. Check with:
  `grep -rnE '^\s*function [a-z][a-z0-9]*_[a-z0-9_]*\s*\(|function [a-zA-Z]*[A-Z][a-zA-Z]*\s*\(' --exclude-dir=vendor .`
  which must print nothing.
- **Database naming is ONE word too — tables, columns, indexes and constraints.** No `_id` suffix (the column *is* the reference: `songs.artist`, `charts.song`, `favorites.user`), no `_at` suffix (the column is the timestamp: `created`, `updated`, `expires`, `used`, `login`, `verified`), no `_file`/`_count` qualifier (`songs.audio`, `songs.plays`, `songs.downloads`, `icons.css`). Indexes keep a conventional prefix plus one word (`idx_*`, `uq_*`, `fk_*`); FK names must be unique per *database*, not per table, so the three tables that reference `songs` are `fk_chart`, `fk_event` and `fk_favorite`. The rename is **DB-layer only**: `$_SESSION` keys, PHP locals, HTML field names and JS payloads keep what they used (`api/icons.php` deliberately still emits the JSON key `fa_class` because `app.js` reads it). Check with:
  `grep -rnE '\b(auth_tokens|song_events|account_type|user_id|token_hash|expires_at|used_at|created_at|updated_at|song_id|fa_class|user_agent|actor_id|actor_name|details_args|is_read|page_key|setting_key|setting_value|artist_id|requested_by|category_id|audio_file|play_count|download_count|last_login|email_verified_at|status_code)\b' --include='*.php' --exclude-dir=vendor`
  which must print nothing but `$_SESSION`/local-variable uses.
- **No `static` members or methods.** `bootstrap.php` builds exactly one object of each class per request and injects collaborators as **required** constructor parameters (`User::__construct(DB, Analytics, Settings, Mail)`, `Music::__construct(DB, Analytics, User)`, `Mail::__construct(Analytics)`, `Settings::__construct(DB)`, `Analytics::__construct(DB)`, `Pages::__construct(DB)`), so a second `new DB()` — and therefore a second mysqli connection — cannot happen by accident. Access control is `$user->check('admin')` / `$user->guard('staff')` / `$user->authed()` — never `User::check(...)`. The four stateless helpers that used to be `static` (`agent()`, `referer()`, `normalize()`, `cached()`) are now global functions in `functions.php`; `normalize()`/`cached()` read the public `User::SESSION_ROLES` const. The only `static` left in the codebase is the `static fn` arrow-closure form (two of them — in `functions.php` and `bootstrap.php`), which is fine. The two helpers that still need the database (`icons()`, `slug()`) reach the one connection with `global $db;` — a `static` local to memoize is a regression (`icons()` uses a request-scoped `$iconCache` global instead).
- **Use the OOP classes.** DB writes go through `$db->execute()/insert()/row()/select()/scalar()` — always parameterized, types auto-detected. Domain logic goes in the matching class, never inline in a page.

## Architecture

- **One class per file in `app/`**, no autoloader — `db`, `settings`, `user`, `music`, `analytics`, `mail`, `pages`, required directly by `bootstrap.php` in that fixed order.
- **`app/functions.php` = all 32 general helpers in one file**, split by `/* --- */` section banners (request & client address, session/redirects/flash, output, countries, URLs & slugs, images, uploads, formatting, pagination, CSRF, validation). Do not re-split it; add a new helper to the section it belongs to. It emits **no markup** — the 19 markup-emitting helpers were removed to guarded partials in `app/includes/partials/` (`theme-script.php`, `css-links.php`, `js-links.php`, `alert.php`, `flash.php`, `pagination.php`, `page-header.php`, `empty-state.php`, `song-grid.php`, `song-card.php`, `artist-card.php`, `delete-button.php`, `stat-card.php`, `country-options.php`), each opening with an `if (!defined('APP_BOOTSTRAPPED'))` guard so it can never be requested directly, and one-off markup is written literally in the page. `icon()` is the one grandfathered exception: it is a lookup helper that returns an `<i>` tag, not a block helper.
- **English-only — there is no string, i18n or keyword layer.** Every string is written literally at its point of use (`<?= e("Plays") ?>`, `sprintf("Song: %s", $title)`), English is the current *and always default* language, and there is no `languages`/`translations` table, no `?lang=` switcher, no catalog, no `setlocale()`, no `Accept-Language` handling, no `Intl*` formatter, no `t()/t_raw()/translate_message()/string_catalog()/js_translations()`, no `lib/strings.php`, no `window.GT`, and no per-page-language columns (the SEO columns were renamed `title_en`/`description_en`/`keywords_en` → `title`/`description`/`keywords`). The seven `<html lang="en">` attributes are the only language-adjacent markup and they stay. Do not reintroduce a locale or a keyword layer. The consequences:
  - Method returns use `['success' => …, 'message' => …]` with the `message` as **finished display text**; the 48 snake_case keys (`login_failed`, `email_taken`, …) were inlined and there is no resolver downstream.
  - `flash()` and `Analytics::log($action, $details)` take finished display text too — build parameterized text with `sprintf()`. The old array shape `['key' => ..., 'args' => [...]]` is gone; passing it does not throw (the parameter is untyped) but silently casts to the literal string `"Array"`.
- **Merged with a mode argument, never duplicated wrappers.** Where a method differed only by role/type/kind/scope it takes that argument and maps it through a private const table: `User::delete($role,$id)` (+`DELETE_META`), `User::toggle($id,$role)`, `User::find($id,$role)`, `User::save($role,…)`, `User::roster($role,$withCount)`, `User::total($role)`, `Music::increment($id,$type)`, `Music::ranked($order,…)` (+`SONG_ORDER`), `Music::status($type,$id,$status)`, `Music::save($type,…)`/`Music::delete($type,…)`, `Music::categories($songId=null)`, `Music::search($q,$slim)`, `Analytics::clear($target,…)` (+`CLEAR_TABLES`), `Analytics::stats($kind)`, `Analytics::badge($subject,$value)`, `Mail::send($kind,$data)` (`verify`/`reset`/`changed`/`contact`). The per-role wrappers (`deleteArtist`, `saveAdmin`, `findArtist`, `countAll`, `latest`/`popular`, …) were removed — **`Music::ranked()` replaced the `latest()`/`popular()` pair** (identical query, differing only in ORDER BY). The few pairs still separate, and why: `Music::categories()` vs `all()` (the latter's `song_count` subquery and filter flags have no counterpart); `Music::song($slug)` vs `Music::download($slug)` (the latter *performs* the increment + download log, so merging puts a side effect inside the read path); the login-throttle helpers are now `key()/state()/clear()` scoped rather than one method per target. **When you widen a signature, validate the new argument** — an unknown `$type`/`$role`/`$kind`/`$scope` must return early rather than fall through: `increment()` returns early because `song_events.type` is an enum and a bad value is a *fatal on insert*, not a no-op, and `Analytics::clear()` takes a *logical* name and looks the physical table up in `CLEAR_TABLES` so no caller string is ever interpolated into a `DELETE`.
- **Partials communicate through plain local variables** set immediately before the `require` — `$alert_type`/`$alert_text`, `$song`/`$card_opt`/`$card_compact`/`$card_i`, `$grid_items`/`$grid_card_opt`/`$grid_row_open`, `$page_header_title`/`$page_header_subtitle`/`$page_header_content`, `$empty_icon`/`$empty_title`/`$empty_text`/`$empty_cta`, `$current_page`/`$total_pages`/`$base_url`/`$pagination_i`, `$stat_label`/`$stat_value`/`$stat_icon`/`$stat_color`/`$stat_extra`, `$delete_form_class`/`$delete_form_action`/`$delete_form_fields`, `$selected_country`/`$country_disabled`. The include scope is the caller's scope, so every one of those names must be prefixed or set at the call site — an unprefixed name silently clobbers the page's own variable. `song-card.php`/`artist-card.php` read `$song`/`$artist` (prefixed internally as `$card_*`), so a caller that loops itself must be `foreach ($songs as $song)`, never `as $s`.
  - `song-grid.php` owns the "empty list → empty state, otherwise loop through `song-card.php`" block that seven pages used to repeat. It reads `$grid_items`, `$grid_card_opt`, the `$grid_empty_*` trio, `$grid_row_class` (default `row g-4`) and `$grid_row_open`. **`$grid_row_open` must be `true` wherever the caller opens `<div class="row …">` itself** (homepage, search) — the wrapper has to stay open across the empty state there, whereas `music`/`category`/`favorites`/`artist` want it closed around the cards only. Getting this backwards nests the empty state inside a Bootstrap `.row`, where it collapses to content width.
  - `dashboard/admin/includes/account-form.php` and `account-list.php` are role-parameterised (`$role = 'user' | 'admin'`) and own the whole page; `add-user.php`/`add-admin.php`/`users.php`/`admins.php` are 8-line wrappers that set `$role` and require them. Both guard on `!isset($role) || !in_array($role, ['user','admin'], true)` → 403. `account-list.php` is why the list needs `$role` at all: only admin rows self-protect (no disable/delete on the signed-in account), and `$self_id` is `0` for the user list so no row ever matches.
  - **Paths are `__DIR__`-relative and depth-sensitive:** a file needs exactly as many `../` as there are directory levels between it and the docroot. So `pages/x.php` uses `'/../app/includes/partials/'`, `installer.php` uses `'/app/includes/partials/'`, `dashboard/x.php`, `dashboard/admin/x.php` and `dashboard/includes/x.php` use `'/../../app/includes/partials/'`, `dashboard/admin/includes/x.php` uses `'/../../../app/includes/partials/'`, and the shells use `'/../partials/'`. A wrong depth 500s; a wrong asset path silently collapses markup.
- Account security lives in `User` in `app/user.class.php`: `issue()`/`consume()` (one-time tokens; only the SHA-256 hash is stored in `tokens`), `verify()`, `resend()`, `recover()`, `reset()`. Public login is gated on `users.verified`, except `role='admin'`. Pages: `forgot.php`, `reset.php`, `verify-email.php`.
- The three shells are `app/includes/{public,admin,member}/{header,footer}.php`. Pages `require` the one they need; the admin shell guards with `$user->guard('staff')` in its header. Depth: `dashboard/admin/` → `'/../../app/includes/admin/header.php'`, `dashboard/` → `'../app/includes/member/header.php'`, `pages/` → `'../app/includes/public/header.php'`.
- **The installer** is a single self-contained `installer.php` (759 lines) in four ordered sections: 1) helpers (session state, DB connect, `install_schema()`, `install_write_mail_config()`, `install_checks()`), 2) request state (lock check, step number, pre-filled values), 3) POST handlers for steps 3–5 plus read-only re-entry state, 4) the markup for all six steps. Sections 3 and 4 share the file's scope and communicate **only** through `$step` and `$error`/`$notice`/`$success`. **Every write sits behind a POST**, so a GET can only render — no install path runs from a link, a prefetch or a crawler. A post-install button `unlink()`s the file, so the filename appears in several user-facing strings and in `Analytics::visit()`'s skip list — rename it and all of those change.
- `app/config.php` = constants + secure-session/header bootstrap + the `COUNTRY_LIST` const (ISO 3166-1 alpha-2 => English name, single source of truth — `country()`, `valid('country')` and the country partial all read one place).
- **Method return messages, `flash()` and `Analytics::log()` take finished display text — never a key** (see the English-only bullet). A new auth/security event gets a key in `Analytics::ACTIONS`.
- Uploads: `filename()` + `validate($kind,$file)` in `functions.php` (`$kind` = `audio`|`image`). Files land in `assets/audio/`, artist images in `assets/images/`, song artwork in `assets/images/artwork/` — always via the `AUDIO_PATH`/`IMAGE_PATH`/`ARTWORK_PATH` constants, never a `__DIR__` walk.
- URLs: `url()` / `asset()` read `BASE_URL` (see Config & serving). Render dynamic Font Awesome icons with `icon($name, $style, $class, $attrs)` — it accepts plain DB values and resolves legacy aliases; don't hand-build `<i>` tags around a lookup helper.
- Email: send **only** through `$mail` (never `mail()`/PHPMailer inline); it reads the `MAIL_*` constants and logs failures. Keep it best-effort.
- **`e()` is for user input ONLY — never text you typed yourself.** Escape request fields, DB columns a visitor can write, and anything derived from them, at the output boundary. Write static markup literally (`<h2>Latest Releases</h2>`), and do not wrap config constants (`SITE_NAME`, `BASE_URL`). A `sprintf()` needs `e()` when any argument can carry user text and must not when every argument is a constant or number. `e()` on `url()` and `csrf()` output is kept deliberately: `BASE_URL` can be request-derived, so that one is genuinely untrusted. POST handlers check `csrf($_POST['csrf_token'] ?? '')`; forms emit the hidden input literally with `e(csrf())`; AJAX reads the token from `<meta name="csrf-token">`.

## Gotchas (hard-won)

- **A partial's include scope is the caller's scope — the loop variable's name is a contract, not a style choice.** `song-card.php` reads `$song` because that is what the deleted `song_card($song, …)` parameter was called. A call site left as `foreach ($songs as $s)` renders **valid markup with `data-id="0"` and empty titles on every card** — no error, no warning, routing still 200. Name the variable `$song`/`$artist` or set it explicitly before the `require`.
- **`__DIR__` depth is the single most common casualty of a move.** The leading slash in `require __DIR__ . '/../app/...'` means an off-by-one `../` resolves somewhere else entirely (`/var/www/app/…`) rather than erroring loudly. When a page moves, re-derive its partial paths by counting directories between the file and the docroot.
- **`pages/artist.php` has an unclosed `<section class="py-5"><div class="container">`.** Pre-existing and deliberately left alone rather than silently changing public markup in a refactor. Div nesting there ends one level deep.
- **`pages/` cannot be denied over HTTP.** The public rules rewrite to `pages/<name>.php`, and mod_rewrite re-runs the ruleset against its own target; a deny rule for `pages` blocks the router and 403s every public page. Direct `/pages/*.php` and `/dashboard/...` URLs are real duplicate entry points; new public pages need an `.htaccess` rule for a canonical pretty URL.
- **`asset()` must read `ASSETS_PATH`, never `__DIR__`.** When the file moved, a `realpath(__DIR__ . '/../assets')` stopped resolving and every `<link>`/`<script>` silently collapsed to `http://localhost/assets/` — status 200, ~550 bytes smaller on every page. It now reads the constant, which is why the byte-size check matters.
- **The installer's last line matters.** `installer.php` must end with `</html>` and **no** trailing newline — `echo`'s implicit newline hid a real EOF difference in the old four-file split, and the merge's harness caught it on steps 1 and 6.
- **Demo credentials** (live DB, not in any file): `admin@mail.local` / `admin123` (role `admin`, unverified — admins bypass the email gate), `artist@mail.local` (role `artist`, verified), `hiswill@mail.local` (role `user`, verified), `cece-winans@artist.local` (role `artist`, **unverified**, so it cannot log in).
- **Known security debt** (documented, not silently "fixed" without asking): the *login throttle* is session-only — read through `User::state()` which reads only `$_SESSION`, so the persisted `strike()` counters are write-only dead code and throttling resets with the session (the cooldown mechanism is separate, is durable, and works — see the next bullet); CSRF tokens ride in some admin GET URLs; and `app/config.php` is world-readable with the live DB credentials.
- **Only the *login* throttle is dead code — and the purge condition is NOT the cause.** Two separate mechanisms share the `login_lock_` prefix. The *cooldowns* (`cooldown()` reads the row back via `Settings::get()`, `hit()` always writes a future `lock_until`) work and survive sessions; don't purge their rows by hand. The *login throttle* (`strike()`/`state()`/`clear()`) reads only `$_SESSION`, so the DB rows it writes are never read back and any failure below `LOGIN_MAX_ATTEMPTS` leaves `lock_until = 0` → `purge()` deletes the row in the same request. **Do not loosen the purge condition** — nothing reads those rows back; the real fix is to route `state()` through `Settings` like `cooldown()` does, which changes security behaviour and was deliberately left awaiting a decision.
- **`database.sql` cannot be pointed at a scratch database.** It hardcodes `USE zora;` and drops every table first, so `mysql zora_scratch < database.sql` still resets the **live** tables — it destroyed the live demo rows on 2026-10-02. Never pipe it anywhere without reading its first 30 lines; to validate the schema, `sed` the `USE`/database name out to a scratch copy or extract only the `CREATE TABLE` blocks. Then take a `mysqldump` before touching the DB at all.
- **The demo rows live only in the live DB** and `database.sql` re-seeds only `pages`. Any test that mutates data changes them permanently — and some writes have easy-to-forget side effects: logging in bumps `users.login`, viewing `/charts` **rebuilds** the `charts` table, and `/song/*` or `/download/*` bumps `plays`/`downloads` and appends `events` rows. Clean up by the exact ids returned by the create call, never by guessing at list order.
- **Font Awesome webfonts live in `assets/webfonts/`** because `assets/css/all.min.css` references `../webfonts/`. There is no `@font-face` block in `style.css` anymore.
- **Design lives entirely in one file:** `assets/css/style.css` (design tokens in `:root`, theme via `[data-theme]` on `<html>`). Don't reintroduce `modern-theme.css`/`style2.css` or add theme-override stylesheets. Dark/light theming is driven by `app/includes/partials/theme-script.php` (required pre-paint by every shell, avoids flash) + `Theme` in `assets/js/app.js`; keep the two in sync on `data-theme-mode`/`data-theme`. There is **no Auto/system choice** — the toggle is Light↔Dark only, and a visitor with no saved preference follows the OS `prefers-color-scheme` (live-updating).
- **Website-management routes** (`dashboard/admin/logs|logins|visits|downloads`, mapped by `.htaccess`), under the "System" nav group in the admin sidebar, read the `logs`/`logins`/`visitors`/`songs` tables through the shared `$analytics` instance — never `new Analytics()`. Both tracking tables name their browser-string column `useragent`, and `Analytics::login()`/`visit()` are its only writers; if either column is renamed, all four SQL spots in `analytics.class.php` and both column definitions in `database.sql` must move together or tracking dies *silently* (`DB::execute()` returns `false` instead of throwing).
- **Demo media exists now** (unlike the placeholder 0-byte days): `assets/audio/come-jesus-come-cece-winans.mp3`, `assets/images/artist.png`, `assets/images/artwork.png`, `assets/images/logo.png` and `assets/images/placeholder.svg`. Homepage/`image()` still fall back to `placeholder()` when a row has no stored path.
- **Email and webmail live outside this repo.** Roundcube and phpMyAdmin are served from `/var/www/local/` (`http://local/pma`, `/local/mail`), by `local.conf` (DocumentRoot `/var/www/local`, bare root 403). Roundcube is aliased from `/mail` to its `public_html/` so `program/`, `config/`, `logs/`, `temp/` stay unreachable; phpMyAdmin is a **copy** of `/usr/share/phpmyadmin` (re-copy after a `phpmyadmin` apt upgrade) reading `/etc/phpmyadmin/config.inc.php`. `000-default.conf` deliberately claims **no** `ServerName`/`ServerAlias` (it used to claim `localhost`/`127.0.0.1` and shadow `local.conf`); never put an `Alias` outside a `<VirtualHost>`, and note Roundcube's `logs/`/`temp/` are `www-data`-owned because mod_php runs as `www-data`.
- **The member dashboard is a folder, not a query-string page.** `/dashboard` is the role-based overview; sections are `dashboard/profile`, `dashboard/songs` (artist-only, posts `action=save`), `dashboard/add-song` (artist-only), `dashboard/song-requests` (user-only), `dashboard/favorites`, `dashboard/playlists`, under the member shell. The old `?tab=` routing on a root `dashboard.php` is gone.
- **The playlist method names are one word each and look arbitrary on purpose:** `playlists()` (owner's list), `discover()` (public playlists), `playlist()` (by slug), `owned()`, `visible()`, `tracks()`, `compose()` (create or update), `attach()`/`detach()` (add/remove a song), `move()` (reorder one step), `erase()` (delete, owner-scoped), `holds()`. They are not `getPlaylist`/`addToPlaylist` pairs — see the one-word rule.
- **Playlists are two tables, `playlists` + `playlistitems`.** `playlists` is owner-scoped like `favorites` (no FK, deleted by hand), with `privacy enum('public','private')`, a `slug`, a denormalized `songs` counter and an unused `cover` column. `playlistitems` is the join (`playlist`, `song`, `position`) with `uq_item` on `(playlist, song)` and `fk_playlistitem_song` cascade-deleting with the song. **`Music::move()` swaps by parking the moved row on `position = 1000000` for one statement** — do not "simplify" it to add-then-subtract the same offset, which is arithmetically a no-op that reports success and reorders nothing (`attach()` hands out contiguous positions from `MAX(position)+1`, so `1000000` is a safe sentinel). Only `attach()`/`detach()` maintain the `songs` counter.
- **`playlist` is one route prefix carrying two pages.** `/playlists` is the login-only manage page (`pages/playlists.php`) and `/playlist/<slug>` the public detail (`pages/playlist.php`), so `playlist` appears in **both** the slug-carrying and the plain rewrite rules. Detail 404s are decided by `Music::visible()`, so a private playlist 404s for non-owners instead of 403ing. The picker is a client-rendered Bootstrap modal (`PlaylistPicker` in `app.js`); two of its behaviours are contracts: an empty state that **autofocuses the create field**, and a per-playlist **`has`** flag from `api/playlist.php`'s `list` action so an already-added playlist renders disabled with an "Added" badge. The list is refetched on every open (never cached) because membership and counts change from the manage page in another tab. Playlist names arrive as raw JSON and are dropped into `data-name="…"` by string concatenation, so they go through the `attr()` helper in `app.js` — the server-side `e()` on the manage pages does not protect that path.
- **Song requests live in the `songs` table.** A `user` requests via `Music::request()` → a `songs` row with `status='requested'`, `audio_file=''`, `requested_by` set; an admin approves (`Music::approve()` → `'approved'`); the owning artist uploads audio (`Music::publish()`), which publishes it. `songs.status` is `enum('pending','published','draft','requested','approved')`; `save()` accepts `requested`/`approved` but `status('song',…)` does not. Dedupe runs on `(artist, title)` among `requested` rows.
- **Artists are hidden from public surfaces until they have ≥1 published song.** `User::artists()`, `User::artist()`, `Music::search()` (page and `$slim` AJAX shapes) filter with `EXISTS (SELECT 1 FROM songs s WHERE s.artist_id = <alias>.id AND s.status = 'published')`. Watch the alias: `artists()` aliases `users a`, so the EXISTS uses `a.id` there, while `artist()` and `Music` use unaliased `users.id`. Admin pickers (`options()`, `search()`, artist lookup) stay unfiltered.
- **Public login requires `users.verified`.** New registrations start NULL and are blocked at login (a `blocked` attempt) with a resend option; admin login is exempt. Test registrations need the verification step (or a manual DB update) before they can sign in.
